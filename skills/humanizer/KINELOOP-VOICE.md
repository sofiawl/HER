# Kineloop (cards, comments, documents)

Language: **Brazilian Portuguese**. Code identifiers, paths, API field names, and card IDs stay as in the draft.

## Cards and documents

- Title: one line, specific, verb or outcome first when it fits ("Corrigir …", "Adicionar …", "Medir …").
- Description: context in two or three short paragraphs max, then bullets for acceptance criteria or steps if the draft already lists them.
- Same honesty as PR voice: name the weird edge case, the thing that looks broken but is expected, the dependency on another card.
- Impersonal or "eu" is fine when the draft already uses it; do not add author diary ("decidi deixar assim porque …") unless it was in the draft.
- Links: only committed URLs or `https://loop.zslippy.com/issue/<CARD>`. Never `.scratch/` or uncommitted paths.

## Comments

- One or two short paragraphs, or a tight bullet list when the draft is already a list.
- Direct answer first, detail second. No "Obrigada por …" opener unless Sofia pasted that herself.

## Shape

- Decimal comma in Portuguese prose; keep English technical terms the team uses (pipeline, ground truth) in italics only if the draft already italicizes them.
- Bold sparingly for the one phrase a skimmer must see.
